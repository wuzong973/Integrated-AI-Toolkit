# 一、项目概述与设计基线

## 1.1 项目定位

青智校园不是单纯的 AI 聊天机器人，也不是普通的校园跑腿平台，而是三层能力叠加的复合平台：

| 组成 | 定位 | 一句话职责 |
|---|---|---|
| **青智 OS** | AI 智能中枢 / Agent 编排系统 | 理解目标 → 拆解任务 → 调度工具与人力 → 跟踪结果 |
| **青智 AI 工具箱** | 面向大学生的一站式 AI 生产力工具 | 把"想法"直接变成 `pptx / docx / pdf / mp4 / mp3 / 图片` 等真实产物 |
| **青智驿站** | 校园技能服务与任务协同平台 | AI 干不了的活，匹配真实的学生服务者完成 |

三者在小程序内收敛为一个入口，形成完整闭环：

```
用户提出目标
  → AI 理解需求（意图识别）
  → AI 拆解任务（任务规划 DAG）
  → 判断哪些可由 AI 自动完成 → 调用对应 AI 工具（Tool Registry）
  → 判断哪些需要真人完成   → 在青智驿站匹配服务者 → 创建任务/订单
  → 服务执行（Human-in-the-loop 介入）
  → 结果验收
  → 用户评价
  → 更新技能画像与信用体系
  → 反哺下一次智能匹配
```

**核心理念**：`AI 负责理解和规划，AI 工具负责标准化执行，青年负责复杂任务执行。`

## 1.2 角色体系

| 角色 | 说明 | 主要入口 | 核心诉求 |
|---|---|---|---|
| 学生（普通用户） | 在校大学生，需求发起方 | 小程序用户端 | 提需求、用工具、发任务、评价 |
| 服务者（达人） | 具备技能并通过认证的学生 | 服务者端（小程序内切换身份） | 接单、交付、提现、积累信用 |
| 社团 / 学院 / 学校 | 组织方，发布活动与官方需求 | 组织管理端（H5/Web） | 活动发布、报名管理、审核、数据看板 |
| 商户 | 校园周边商家 | 商户端（H5/Web） | 发布服务商品、核销、结算 |
| 平台管理员 | 运营方 | 平台管理后台（Web） | 审核、配置、风控、监控、结算对账 |

> **身份设计**：小程序内不按端拆包，采用"**一账号多身份**"模型 —— 同一微信账号可同时是「普通用户」与「认证服务者」，通过顶部身份切换器切换，避免重复注册与多小程序跳转。

## 1.3 设计原则（硬性约束）

以下 10 条为开发红线，任何方案评审必须逐条比对：

| # | 原则 | 落地要求 |
|---|---|---|
| 1 | 核心流程真正可运行 | 首版只做 3 条主链路，但必须端到端跑通（见 1.4） |
| 2 | UI 现代、完整、专业 | 统一设计系统（第 4 章），禁止页面各写各的样式 |
| 3 | 前后端真实联通 | 全部页面走真实 API，禁止本地假数据 |
| 4 | 数据库真实工作 | 所有状态落库，禁止内存态模拟 |
| 5 | AI 功能能够实际调用 | LLM / OCR / FFmpeg 等必须真实调用并返回真实产物 |
| 6 | Demo 能够完整演示 | 提供一键演示脚本与预置演示账号 |
| 7 | 后期可以部署上线 | 全容器化，配置外置，无本地绝对路径硬编码 |
| 8 | 代码结构清晰 | 分层 + 模块化，单文件不超过 300 行 |
| 9 | 模块可以独立替换 | 全部外部依赖走 Provider 抽象层 |
| 10 | 禁止假数据冒充功能 | MockProvider 必须在响应头/日志中显式标记 `X-Provider: mock` |

## 1.4 Provider 抽象层（原则 9 的工程实现）

所有第三方能力必须定义接口，开发期用 `MockProvider`，上线时替换真实实现，**业务代码零改动**。

| Provider | 职责 | 开发期实现 | 生产实现 | 备注 |
|---|---|---|---|---|
| `LLMProvider` | 文本/多模态大模型推理 | `MockLLMProvider`（规则回放） | 多模型路由（DeepSeek / Qwen / GPT / Gemini） | 需支持流式、Function Calling、超时降级 |
| `StorageProvider` | 对象存储 | 本地磁盘 | 腾讯云 COS / MinIO | 统一返回可访问 URL + 直传签名 |
| `OCRProvider` | 文字识别 | `MockOCRProvider` | PaddleOCR / 腾讯 OCR | 优先本地部署控本 |
| `PPTProvider` | PPT 生成 | PptxGenJS（本地即可跑通） | PptxGenJS + 模板服务 | 必须真实产出 `.pptx` |
| `AudioProvider` | 音频处理 | FFmpeg | FFmpeg + faster-whisper + Demucs | GPU 任务走异步队列 |
| `VideoProvider` | 视频处理 | FFmpeg | FFmpeg（+ GPU 转码可选） | 异步 |
| `ImageProvider` | 图片处理 | Sharp / ImageMagick | Sharp + rembg（抠图） | 抠图走 GPU |
| `DocProvider` | 文档转换 | LibreOffice / Pandoc | 同上，独立服务部署 | 与 AGPL 组件隔离部署 |
| `PayProvider` | 支付 | MockPayProvider | 微信支付 + 余额钱包 | 担保交易模式 |
| `NotifyProvider` | 消息推送 | MockNotifyProvider | 微信订阅消息 + 站内信 + WebSocket | 需申请订阅消息模板 |
| `ModerationProvider` | 内容安全 | 本地敏感词库 | 微信内容安全 API + 词库 | 双层校验 |

> **统一约定**：所有 Provider 实现同一接口契约 `execute(input, ctx): Promise<Result>`，并内置 `idempotencyKey`、超时、重试与降级策略（详见 5.4.5）。

## 1.5 开源使用与合规策略

采用路线：**开源基础能力 + 自研统一 API 层 + 自研 AI 任务编排 + 自研校园场景逻辑**。

- 建立 `/docs/compliance/OPEN_SOURCE_LICENSES.md`，逐项登记：组件 / 版本 / 仓库 / License / 是否商用 / 署名要求 / 模型 License / 使用位置 / 风险说明。
- **可用层（MIT / Apache-2.0）**：PptxGenJS、Demucs、rembg、faster-whisper、PaddleOCR、Langflow、MetaGPT、Presenton。
- **隔离层（AGPL / GPL，禁止并入闭源内核）**：ConvertX、PPTist、it-tools、PowerTools —— 以**独立服务 + HTTP API** 方式接入，不复制源码。
- **评估层**：Dify（Apache-2.0 附加条款）、n8n（Fair-code）、UVR（模型权重独立许可，常见 Research Only）。
- **红线**：License 不明确的一律不作为生产依赖；模型权重许可必须单独核查。
- 自研核心（必须自己写，构成比赛技术壁垒）：`Agent Runtime`、`Tool Registry`、`任务 DAG 编排引擎`、`驿站匹配与信用算法`、`校园场景知识库`。

## 1.6 首版三条主链路（P0）

| 链路 | 起点 | 终点 | 验证标准 |
|---|---|---|---|
| **L1 AI 工具链路** | 首页输入"帮我做一份创新创业比赛 PPT" | 下载到真实 `.pptx` 文件 | 文件可打开、页数与主题一致 |
| **L2 AI 编排 + 人力协同链路** | 输入"办一场 200 人双创活动，预算 3000" | 生成方案 + 自动派发摄影/主持任务到驿站 | 驿站出现真实任务卡片，可接单 |
| **L3 服务交易链路** | 驿站发布"找人拍毕业照" | 接单 → 交付 → 验收 → 评价 → 结算 | 状态流转完整，评价后信用分变化 |

# 二、整体架构设计

## 2.1 端侧形态与技术选型

| 端 | 形态 | 技术栈 | 说明 |
|---|---|---|---|
| **微信小程序（主端）** | 原生小程序 | TypeScript + 小程序自定义组件 + `skyline`（可选渐进） | 校园场景主入口，微信登录/支付/订阅消息原生能力最优 |
| H5 / Web 用户端 | 响应式 Web | Taro 4 + React 18 同构输出 或 独立 React SPA | 与小程序**共享 `packages/core` 领域层与 API SDK** |
| 管理后台 | Web | React + Ant Design Pro | 平台/组织/商户端共用一套后台框架，按权限裁剪菜单 |
| 开放能力 | HTTP API | RESTful + OpenAPI 3.0 | 保证未来任何端（App/小程序/H5）复用同一后端 |

> **多端复用策略**：业务逻辑、领域模型、请求封装、状态机定义在 `packages/core`（纯 TS，无端侧 API 依赖），小程序与 H5 各自只实现视图层与端能力适配（登录、支付、上传、推送）。

## 2.3 后端服务拆分

| 服务 | 技术 | 职责 | 部署形态 |
|---|---|---|---|
| `qz-gateway` | NestJS | 统一 API 入口、鉴权、限流、路由 | 无状态，可水平扩展 |
| `qz-user` | NestJS | 用户、身份、认证资质、组织、信用 | 无状态 |
| `qz-toolbox` | NestJS | 工具目录、执行单、文件资产、结果回调 | 无状态 |
| `qz-station` | NestJS | 服务市场、需求/任务、订单、评价、纠纷 | 无状态 |
| `qz-pay` | NestJS | 钱包、支付、担保、结算、提现 | 无状态 |
| `qz-msg` | NestJS + WS | 会话、IM、通知、订阅消息、事件推送 | 有状态（WS 节点，Redis 广播） |
| `qz-os` | NestJS（编排） | 青智 OS：会话、意图、规划、DAG、HITL、Agent 调度 | 无状态 |
| `qz-agent-runtime` | Python / Node | Agent 运行、LLM 调用、工具执行代理 | 无状态 |
| `qz-media-worker` | Python | FFmpeg / Whisper / Demucs / rembg / OCR 重型任务 | **有状态 worker，GPU 可选** |
| `qz-doc-worker` | Python + LibreOffice | 文档转换（**独立部署，隔离 AGPL/GPL 组件**） | worker |
| `qz-search` | ES + 向量库 | 搜索、推荐、知识库检索 | 独立 |

> **拆分原则**：比赛阶段可合并部署为 3 个进程（`api` / `os` / `worker`），但代码必须按模块边界隔离，保证后期可拆分。

```
│   │   ├── categories.ts      # 工具分类与权限矩阵
│   │   └── defs/              # 每个工具一个定义文件（schema + handler）
│   ├── orchestrator/          # 任务编排引擎
│   │   ├── planner.ts         # 目标 → DAG
│   │   ├── scheduler.ts       # 拓扑排序 + 并行调度 + 依赖检查
│   │   ├── state-machine.ts   # 节点/计划状态机
│   │   ├── hitl.ts            # Human-in-the-loop 网关
│   │   └── recovery.ts        # 失败重试 / 补偿 / 降级 / 回滚
│   ├── providers/             # Provider 抽象层（接口 + 实现）
```

## 2.6 关键架构决策（ADR 摘要）

| 编号 | 决策 | 备选方案 | 结论与理由 |
|---|---|---|---|
| ADR-01 | 小程序主端用原生 + TS | Taro/uni-app | 选原生：微信能力（登录/支付/订阅消息/文件打开）最完整、性能最好；业务逻辑抽到 `packages/core` 保证 H5 可复用 |
| ADR-02 | 编排层自研而非直接用 Dify/n8n | Dify / Langflow | 选自研轻量编排（借鉴其状态机与 HITL 设计）：Dify 有附加条款、n8n 禁止转售，且自研编排是本项目核心技术壁垒与评分点 |
| ADR-03 | 重型媒体任务走异步队列 | 同步阻塞 | 选异步：FFmpeg/Demucs 耗时数十秒到数分钟，同步必超时；小程序侧用轮询 + WebSocket 双通道推进度 |
| ADR-04 | 文件直传对象存储 | 经后端中转 | 选直传：后端下发临时签名，小程序 `wx.uploadFile` 直传，避免后端带宽瓶颈与大文件超时 |
| ADR-05 | 文档转换服务独立部署 | 主服务内嵌 LibreOffice | 选独立部署：隔离 AGPL/GPL 组件，避免衍生作品开放义务，同时资源隔离（转换服务吃 CPU/内存） |
| ADR-06 | 一账号多身份 | 多端分包 | 选一账号多身份：降低注册摩擦，让"发布需求的人"天然可能变成"接单的人"，提升供给侧转化 |
| ADR-07 | 支付采用担保交易 | 直接支付 | 选担保：钱先进平台托管账户，验收后放款，匹配校园任务类交易纠纷场景 |

| 依赖 | 用户/服务者服务、支付服务、消息服务、信用服务 |

## 4.5 多端与适配

| 场景 | 方案 |
|---|---|
| 深色模式 | `theme-dark.scss` 覆盖 CSS 变量，支持跟随系统 + 手动切换，持久化到服务端用户配置 |
| 大屏/Pad | 列表由单列改双列（`grid-template-columns` 响应式），最大内容宽度 1200rpx 居中 |
| H5 | 复用 `packages/core`；导航由 TabBar 改为顶部导航 + 侧边栏 |
| 字体缩放 | 关键文本禁止使用 `px` 固定高度容器包裹，允许换行；最小字号不小于 20rpx |
| 无障碍 | 所有可点击元素加 `aria-label`/`hover-class`；色彩不作为唯一状态区分（配图标/文案） |
| 性能 | 首屏骨架屏；图片 WebP + 懒加载；长列表分页 20 条；`setData` 单次 < 32KB；分包加载（工具箱/驿站/服务者端各自分包） |

## 5.1 用户与权限体系

### 5.1.1 登录与账号

| 环节 | 方案 |
|---|---|
| 登录 | 小程序 `wx.login` 获取 code → 后端换 `openid/unionid` → 签发 JWT（access 2h + refresh 30d） |
| 手机号 | `getPhoneNumber` 授权解密绑定（涉及交易与实名必须） |
| 学生认证 | 姓名 + 学号 + 学校 + 学信/教务/校园邮箱/学生证 OCR 三种方式任选；后台审核 + 自动规则校验 |
| 会话保持 | 小程序端存 `storage`，启动时静默刷新；失效跳登录页并保留当前路由，登录后回跳 |
| 退出 | 清除本地态 + 服务端 refresh token 失效 |

### 5.1.2 角色与权限（RBAC + 数据权限）

```
角色 role: guest | student | provider | org_admin | merchant | platform_admin
权限 permission: 资源:动作       例：tool:ppt:run / station:task:publish / order:pay / admin:audit
身份 identity: 一个 user 可拥有多个 role，全局身份切换器决定当前上下文
数据权限 scope: self | org:{id} | school:{id} | all
```

| 能力 | guest | student | provider | org_admin | admin |
|---|---|---|---|---|---|
| 浏览首页/工具/服务 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 运行 AI 工具 | 试用 1 次 | ✅（消耗积分） | ✅ | ✅ | ✅ |
| 发布驿站需求 | ❌ | ✅ | ✅ | ✅ | ✅ |
| 接单/抢单 | ❌ | ❌ | ✅（需认证+技能） | ❌ | ❌ |
| 提现 | ❌ | ❌ | ✅ | ✅（组织账户） | ✅ |
| 审核/配置 | ❌ | ❌ | ❌ | 本组织 | 全平台 |

### 5.1.3 积分与额度

- 新用户赠送 20 积分；学生认证 +30；每日签到 +2（上限 60/月）；邀请好友 +10/人。
- 工具计费：见 5.5 工具清单的"计费"列；AI 编排按节点计费（简单 1 分/节点，含 LLM 深度生成的 3 分/节点）。
- 积分不足：弹出充值/任务引导；**不得静默失败**。

## 5.2 青智 OS 会话与编排（核心）

### 5.2.1 会话数据模型

```
Session { id, userId, title, scene, agentStack[], contextSummary, status, createdAt, updatedAt }
Message { id, sessionId, role: user|agent|system|tool, agentName, contentType,
          content, cards[], toolCalls[], tokens, createdAt }
```

- **上下文管理**：超过 12 轮或 8k tokens 触发"上下文压缩"——由 LLM 生成 `contextSummary` 并保留最近 4 轮原文，长期画像（专业、年级、偏好风格、常用工具）写入用户 Profile。
- **会话持久化**：所有消息落库，支持历史会话列表、搜索、重命名、删除、导出。

### 5.2.2 意图识别

| 意图 | 说明 | 路由目标 |
|---|---|---|
| `ai_generate` | 内容/文档生成（PPT、文案、策划、简历） | 内容类 Agent + 生成工具 |
| `file_process` | 文件/媒体处理（转换、压缩、OCR、分离） | 文件/媒体 Agent + 处理工具（**不调 LLM 生成内容**） |
| `human_service` | 需真人完成（摄影、主持、维修、跑腿） | 校园服务匹配 Agent → 驿站 |
| `campus_info` | 校园信息查询（公告、制度、活动） | 客服 Agent + 知识库 RAG |
| `composite` | 复合目标（办活动、做项目） | Coordinator → 任务规划 |
| `chitchat` | 闲聊 | 客服 Agent 轻量应答 |

**识别方式**：`规则关键词 + 小模型分类 + LLM 兜底` 三级，优先保证成本与速度；识别置信度 < 0.6 时走**澄清追问**（最多 2 轮）。

### 5.2.3 任务规划（目标 → DAG）

Coordinator Agent 输出结构化计划：

```json
{
  "goal": "举办200人校园创新创业活动，预算3000元",
  "nodes": [
    { "id": "n1", "name": "活动方案", "type": "ai", "agent": "event_planner",
      "tool": "generate_document", "depends": [], "est_cost": 3 },
    { "id": "n2", "name": "预算表",  "type": "ai", "agent": "event_planner",
      "tool": "generate_document", "depends": ["n1"], "est_cost": 2 },
    { "id": "n5", "name": "摄影摄像", "type": "human", "agent": "campus_matcher",
      "tool": "create_task", "depends": [], "est_budget": 300,
      "hitl": "confirm_publish" },
    { "id": "n6", "name": "现场主持", "type": "human", "agent": "campus_matcher",
      "tool": "create_task", "depends": ["n1"], "est_budget": 500,
      "hitl": "confirm_publish" }
  ]
}
```

**规则**
- 输出必须是合法 JSON（用 JSON Schema 强校验，失败重试 1 次，再失败降级为线性清单）。
- 节点数上限 12；type 只能为 `ai` / `human` / `hitl` / `external`。
- `human` 节点必须含预算、技能标签、时间窗口；`depends` 不能成环（拓扑排序校验）。
- 计划生成后**必须经用户确认**（HITL）才执行付费节点；AI 免费节点可自动执行。

### 5.2.4 执行调度

| 机制 | 说明 |
|---|---|
| 拓扑排序 | 按 `depends` 计算层级，同层节点最大并行 3 个 |
| 同步/异步 | 预计 < 8s 的工具同步执行；否则投递 MQ，返回 `jobId`，前端轮询（2s）或 WebSocket 推送进度 |
| 状态机 | 见 5.2.6 |
| HITL | 命中 `hitl` 字段或节点失败 2 次 → 挂起并推送"待确认"卡片 |
| 错误恢复 | 工具超时/失败 → 指数退避重试（1s/4s/16s，最多 3 次）→ 换 Provider 降级 → 仍失败则挂起并给出人工建议（如转驿站） |
| 预算守卫 | 单次编排 LLM token 与积分消耗上限可配置，超限暂停并通知用户 |
| 幂等 | 每个节点执行带 `runId + nodeId + attempt` 幂等键，重复提交不重复扣费 |

### 5.2.5 Human-in-the-loop 类型

| 类型 | 触发 | UI 形态 | 超时策略 |
|---|---|---|---|
| 确认型 | 付费/发布/不可逆操作 | 双按钮（确认/取消） | 24h 未响应自动取消并释放资源 |
| 选择型 | 多个方案（如 3 版海报） | 方案卡片 + 单选 | 无超时，保持挂起 |
| 补充型 | 缺参数（时间/预算/地点） | 内联表单气泡 | 24h 提醒一次 |
| 接管型 | 工具连续失败 | "AI 遇到困难，是否转人工" | — |
| 验收型 | 人力任务交付 | 任务详情验收区（复用订单验收） | 7 天自动验收（可配置） |

### 5.2.6 计划与节点状态机

```
计划 PlanRun:
  draft ──confirm──► running ──all done──► completed
                       │  ├─ hitl ──► waiting_user ──resume──► running
                       │  └─ fail  ──► partial_failed ──► completed | cancelled
  draft/running ──user cancel──► cancelled

节点 TaskNode:
  pending ──dispatch──► queued ──start──► running
                                            ├─success──► succeeded
                                            ├─fail──► retrying ──(≤3)──► running
                                            │              └──(>3)──► failed
                                            └─need_hitl──► waiting_user ──► running|cancelled
  pending/queued/running/waiting_user ──► cancelled（计划终止或用户取消）
```

## 5.3 Agent 体系设计

### 5.3.1 Agent 统一契约

每个 Agent 必须实现且仅实现以下字段，**禁止把逻辑写在一个巨大函数里**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 唯一标识，如 `event_planner` |
| `displayName` | string | 中文名，用于 UI |
| `description` | string | 给 Coordinator 看的职责说明（决定路由） |
| `systemPrompt` | string | 系统提示词（版本号管理，支持热更新） |
| `tools` | string[] | 可调用工具白名单 |
| `permissions` | string[] | 权限点（如 `file:write`、`task:create`、`order:pay:no`） |
| `inputSchema` | JSON Schema | 入参约束 |
| `outputSchema` | JSON Schema | 出参约束（强校验） |
| `maxTokens` / `temperature` | number | 生成参数 |
| `status` | enum | `active` / `shadow`（灰度） / `disabled` |
| `fallbackAgent` | string | 失败降级目标 |

### 5.3.2 Agent 清单（第一阶段 10 个）

| # | name | displayName | 职责 | tools | permissions | 首版状态 |

### 5.3.3 Agent 调度规则

1. Coordinator 永远第一个执行，最后汇总；其他 Agent 由 Coordinator 通过 `dispatch_agent` 调度。
2. 单会话同时运行 Agent 上限 3 个；单 Agent 连续执行上限 5 步，防止死循环（步数超限强制产出并报告）。
3. Agent 输出必须过 **outputSchema 校验 + 安全审核**，不通过则重试 1 次并附错误信息。
4. 所有 Agent 调用记录 `agent_call_log`（tokens、耗时、工具、结果状态），用于成本看板与 Prompt 迭代。

### 5.4.3 调用协议

```jsonc
// 请求
POST /api/v1/tools/{toolName}/invoke
{
  "runId": "uuid",          // 编排 ID（可选）
  "nodeId": "n3",           // 节点 ID（可选）
  "idempotencyKey": "uuid", // 幂等键（必填）
  "async": true,
  "params": { "topic": "创青春商业计划书", "pages": 16, "style": "business" },
  "fileIds": ["file_xxx"]   // 输入文件（引用文件资产，不传二进制）
}
// 同步响应
{ "code": 0, "data": { "jobId": "job_x", "status": "succeeded", "result": { "fileId": "..." } } }
// 异步响应
{ "code": 0, "data": { "jobId": "job_x", "status": "queued", "progressUrl": "/api/v1/jobs/job_x" } }
// 回调/推送（WebSocket 事件 tool.progress）
{ "jobId": "job_x", "status": "running", "progress": 60, "stage": "生成第 10/16 页" }
```

### 5.4.4 权限与配额

- 调用前校验：`role` 是否具备 tool 的 `permissions`；当日调用次数；单文件大小（图片 ≤ 20MB，视频 ≤ 500MB，文档 ≤ 100MB）。
- 上传走**直传**：`POST /files/presign` 获取签名 → 小程序 `wx.uploadFile` 直传 → `POST /files/confirm` 落库生成 `fileId`。
- 涉版权工具（`repair_image`、水印相关）在调用前强制弹出**版权声明勾选**："我确认对该内容拥有版权或已获得合法授权"，未勾选不予执行，并记入审计日志。

### 5.4.5 可靠性约定

| 项 | 策略 |
|---|---|
| 超时 | 同步 15s；异步任务 30min 硬超时，超时置 failed 并退回积分 |
| 重试 | 网络/5xx 指数退避 1s/4s/16s，最多 3 次；业务错误（参数/权限）不重试 |
| 幂等 | `idempotencyKey` 24h 内同键直接返回首次结果 |
| 降级 | LLM 主模型失败 → 备用模型；GPU 队列积压 → 提示预计等待时间，允许用户稍后取结果 |
| 计费 | **仅在 succeeded 后扣费**；失败/超时自动退回预扣 |
| 审计 | 每次调用记录：调用者、参数摘要、耗时、费用、Provider、结果 |

## 5.5 AI 工具箱详细设计

### 5.5.1 工具执行通用流程

```
选择工具 → 上传/选择文件 → 填写参数 → 前端校验 → 预估费用弹窗 → 确认
  → 创建执行单(job) → 扣减预授权积分 → 投递队列 → Worker 执行
  → 进度推送（WS/轮询）→ 产物上传对象存储 → 更新 job=succeeded → 正式扣费
  → 通知用户 → 结果页（预览/下载/下一步）
```

### 5.5.2 AI 办公（P0 优先）

**AI PPT 生成**（明星功能，必须真实产出 `.pptx`）
- 输入：主题*、用途（比赛路演/课程汇报/答辩/其他）、页数（5–40）、风格（商务/科技/清新/学术/国潮）、补充要求、参考资料（可选）。
- 流程：LLM 生成大纲（含页面标题、要点、图表类型、演讲备注）→ JSON 校验 → 选择模板 → PptxGenJS 逐页渲染（文字/形状/图表/图片占位）→ 输出 `.pptx` → 生成封面缩略图。
- 输出：可下载 `.pptx`、封面图、每页缩略图、演讲者备注、大纲 Markdown。
- 约束：禁止编造统计数据，需要数字的用"示例数据"占位并在备注中标注；页数误差 ±2 页内。
- 后续动作：转 PDF、AI 修改（局部重生成）、生成配套路演稿、转驿站找人润色/做路演视频。

其余（AI 商业计划书 / 活动策划 / 简历 / 报告 / 总结）共用同一骨架：模板库 + LLM 分段生成 + DocProvider 渲染为 `docx/md`，输出支持在线预览与下载。

### 5.5.3 图片工具

| 工具 | 输入 | 输出 | 实现 | 备注 |
|---|---|---|---|---|
| 图片压缩 | 图片、目标体积/质量 | 压缩后图片 + 压缩率 | Sharp | 前端可预览对比 |
| 格式转换 | 图片、目标格式(jpg/png/webp/heic) | 转换后图片 | Sharp | — |
| OCR | 图片/PDF | 文本（保留段落）+ 可选双层 PDF | PaddleOCR | 支持中英混排 |
| 背景移除 | 图片 | 透明 PNG | rembg | GPU 队列 |
| 图片增强 | 图片 | 增强后图片 | OpenCV + Real-ESRGAN | 可选 2x/4x |
| 图片修复 | 图片 + 涂抹区域 | 修复后图片 | OpenCV Inpainting | **必须前置版权声明** |

### 5.5.4 视频 / 音频 / PDF / 文件（P1）

- 视频：压缩（按目标 MB 自动计算码率）、转换（MOV/AVI/MKV→MP4 等）、裁剪合并、字幕（Whisper 转写 + 烧录/导出 srt）、（授权内容）修复。
- 音频：格式转换、人声/伴奏分离（Demucs，输出 2~4 轨）、降噪、裁剪、语音转文字（支持时间戳与说话人粗分）。
- PDF：↔Word/PPT/Excel/图片、合并、拆分、加水印、加密、压缩、OCR 双层化。
- 文件：docx/xls/ppt ↔ md/html/pdf、批量转换。

> **成本控制（AI 工具路由器）**：格式转换/压缩类**直接路由到 FFmpeg/Sharp，绝不调 LLM**；只有需要"理解与创作"的才调 LLM。这是成本与体验的分水岭。

### 5.5.5 AI 学习（P1）

解题讲解、论文摘要与翻译、思维导图生成（Markdown→图）、知识点问答（基于课程资料 RAG）、英语作文批改、考公/考研资料整理。

### 5.5.6 文件资产中心

- 统一 `user_files` 资产表：来源（工具产出/用户上传）、类型、大小、有效期、下载次数。
- 列表支持筛选（类型/时间）、搜索、批量下载、转存到"我的文件"、分享（生成带有效期的小程序链接/二维码）、删除（回收站 7 天）。
- 免费存储 2GB / 单文件上限 500MB；文件默认保存 30 天，工具产出文件永久保留（可配置）。

## 5.6 青智驿站详细设计

### 5.6.1 服务与需求模型

```
Service（服务商品）{ id, providerId, title, categoryId, desc, images[], priceType(固定|起步价|议价),
                    price, unit, deliveryDays, skillTags[], status, sales, rating }
Task（需求/任务）  { id, publisherId, title, categoryId, desc, budgetMin, budgetMax,
                    deadline, location{schoolId,poi}, skillTags[], attachments[],
                    assignMode(抢单|派单|指定), status, providerId, source(manual|ai) }
Order（订单）      { id, taskId|serviceId, buyerId, providerId, amount, platformFee,
                    status, payStatus, escrowStatus, deliverables[], timeline[] }
```

### 5.6.2 发布与匹配

| 环节 | 设计 |
|---|---|
| 发布 | 支持 AI 极速发布与标准表单；AI 自动补全分类、技能标签、预算建议、时间建议 |
| 智能推荐 | 匹配分 = `技能匹配 40% + 信用分 25% + 历史评分 15% + 距离/同校 10% + 价格契合 10%` |
| 派单模式 | 抢单（先到先得，限 5 人报名）、派单（AI 推荐 Top3，发布者选择）、指定（直接邀请某服务者） |
| 通知 | 新任务按技能标签推送给匹配服务者（订阅消息 + 站内信），5 分钟未响应扩大推送半径 |
| 估价 | `calculate_price` 基于历史成交价 + 任务复杂度给出建议区间，展示"同类任务均价" |

### 5.6.3 交易与担保

```
创建订单 → 买家支付（钱进平台担保账户）→ 服务者开始服务 → 提交交付物
  → 买家验收（通过 / 要求修改，最多 3 次）→ 放款给服务者 → 双方评价
异常分支：取消（未接单全额退 / 已接单按规则扣违约金）
          退款（双方协商 / 平台仲裁）
          仲裁（超时 7 天未验收自动验收；服务者超时未交付自动退款）
```

- 平台服务费：学生服务 5%（封顶 20 元），商户 8%；提现 T+1，单笔 ≥ 10 元。
- 订单超时规则：未支付 30 分钟自动关闭；已支付未接单 24 小时可申请全额退。

### 5.6.4 评价与信用

| 项 | 规则 |
|---|---|
| 评价 | 双向评价（买家↔服务者），星级 1–5 + 标签（响应快/质量高/沟通顺畅…）+ 图文；评价后 7 天可追评，30 天后不可改 |
| 信用分 | 初始 80，区间 [0,100] |
| 加分 | 完单 +1（上限 +20）、好评 +2、中评 0、及时交付 +1、实名/学生/技能认证 +3/+3/+2 |
| 减分 | 差评 −5、超时交付 −3、违约取消 −5、被仲裁判定有责 −10、虚假交易 −30（并封禁） |
| 权重 | 信用分影响搜索排序、推荐优先级、接单上限、提现额度 |
| 反作弊 | 同设备/同 IP 互刷、订单金额异常、评价文本相似度高 → 风控规则命中后不计分并人工复核 |

```
用户            小程序OS页         qz-gateway          qz-os(Coordinator)     Agent/Tool        驿站
 │                 │                   │                      │                  │              │
 │─输入目标───────►│                   │                      │                  │              │
 │                 │─POST /os/chat────►│                      │                  │              │
 │                 │                   │─创建/复用 session───►│                  │              │
 │                 │                   │                      │─意图识别(composite)              │
 │                 │                   │                      │─LLM 生成 Plan(JSON)──┐           │
 │                 │                   │                      │◄─校验+拓扑排序───────┘           │
 │◄─SSE:计划卡片───│◄──────────────────│◄─────────────────────│                  │              │
 │─[确认执行]─────►│                   │                      │                  │              │

 │                 │                   │                      │                  │─generate_document

 │                 │                   │                      │─human 节点 need_human            │
```

**关键约定**
1. 计划卡片一经确认，节点列表与费用预估**锁定**（展示"预计消耗 X 积分"），执行中新增节点需二次确认。
2. `human` 节点默认**不自动发布**，必须经 HITL 确认（防误发真实订单）。
3. 任一 `ai` 节点失败不影响其他分支继续执行，最终在结果页标注 `partial_failed` 并提供"重试/转人工"。

## 6.4 核心流程二：文件处理类工具（L1 主链路）

```
用户 → 工具箱选工具 → 上传文件(直传OSS) → 填参数 → 预估费用 → 确认
     → POST /tools/{name}/invoke (idempotencyKey)
     → ToolExecutor: 权限校验 → 配额校验 → 预扣积分 → 建 job(queued)
     → 同步? 直接执行 : 投递 MQ
     → Worker(FFmpeg/Sharp/OCR...) 执行，按 stage 上报进度
     → 产物上传 OSS → job=succeeded → 正式扣费 → 事件 tool.job.succeeded
     → 小程序 WS/轮询收到完成 → 结果页(预览/下载/下一步)
```

**AI 工具路由规则**（决定调不调 LLM）：

| 用户意图 | 判定 | 执行 |
|---|---|---|
| "把 MOV 转 MP4" | `file_process` + `video_conversion` | **直接** `convert_video`（FFmpeg），不调 LLM 生成内容 |
| "把视频压到 50MB" | 目标体积明确 | `compress_video`，两遍码率估算或按体积反推码率 |
| "去掉人声" | `audio_separation` | `separate_vocals`（Demucs，GPU 队列） |
| "帮我做 PPT" | `ai_generate` | `generate_outline`（LLM）→ `generate_ppt`（PptxGenJS） |
| "这个 PDF 讲了什么" | `doc_understanding` | `convert_pdf` + OCR（如需）→ LLM 总结 |

```

                                                  │         │
                                                  │      7天自动验收
                                                  ▼
                                             已取消/退款中 ──► 已退款
```

```
草稿 → 待审核 → 已发布(招募中) → 已选定(待支付) → 进行中 → 待验收 → 已完成
                    │                │              │

                    ▼                ▼              ▼

```

## 6.6 权限与数据流转的关键约束

| 约束 | 说明 |
|---|---|
| 单点写入 | 订单状态只能由订单服务写；驿站只发事件，不直接改订单表 |
| 财务一致 | 所有资金变动走支付服务的**双写账本**（账户余额 + 流水），每日对账任务校验 |
| 文件归属 | 所有产物 `fileId` 必须绑定 `userId + scene`，下载接口校验归属（或有效分享令牌） |
| AI 不越权 | Agent 只能调用其 `tools` 白名单内的工具；涉及支付/发布/删除必须 HITL |
| 幂等贯穿 | 创建订单、发起支付、工具调用、任务发布全部强制 `idempotencyKey` |

# 九、非功能性需求

| 类别 | 指标 |
|---|---|
| 性能 | 首页首屏 ≤ 1.5s；API P95 ≤ 300ms（读）/ ≤ 800ms（写）；LLM 首 token ≤ 2s |
| 容量 | 支持 1 万 DAU、峰值 500 QPS；媒体任务并发 10（CPU）+ 3（GPU） |
| 可用性 | 核心服务 99.5%；媒体 Worker 允许降级排队；LLM 多模型容灾 |
| 一致性 | 资金强一致（事务 + 对账）；评价/信用最终一致（事件驱动） |
| 安全 | 全站 HTTPS；敏感字段加密；接口签名与防重放；越权校验统一在网关联调层 |
| 监控 | Prometheus + Grafana：API 成功率/耗时、MQ 积压、Worker 队列、LLM 成本、任务失败率 |
| 日志 | 结构化 JSON 日志 + traceId 全链路；AI 调用单独归集便于成本分析 |
| 灰度 | Agent/Prompt/Tool 支持按 `status=shadow` 灰度；配置中心热更新 |
| 备份 | MySQL 每日全量 + binlog；对象存储跨区域备份；文件 30 天回收站 |
