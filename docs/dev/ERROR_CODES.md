# 错误码表

> 权威定义在代码里：`packages/core/src/errors/codes.ts`（本文件为说明文档，两者必须同步）
> 前端可直接从 `@qz/core` 引入 `ErrorCode` 与 `renderErrorMessage`，避免文案不一致。

## 分段规则

```
0      成功
401xx  认证与授权
403xx  权限与配额
400xx  参数与业务校验
404xx  资源不存在
409xx  状态冲突
429xx  限流
500xx  系统错误
503xx  依赖服务不可用
```

## 文案原则（强制）

> **说清发生了什么 + 用户下一步能做什么。**

禁止「操作失败」「系统错误」「请重试」这类无信息提示。

| 差 | 好 |
|---|---|
| 生成失败 | 处理失败，**积分已原路退回**，你可以 [重试] 或 [转人工] |
| 积分不足 | 积分不足（还差 3 分），去完成任务或充值 |
| 请求失败 | 网络开小差了，点击 [重新加载] 再试一次 |

## 响应格式

```jsonc
// 成功
{ "code": 0, "message": "ok", "data": { ... }, "traceId": "tr_xxx" }

// 失败
{
  "code": 40321,
  "message": "积分不足（还差 3 分），去完成任务或充值",
  "data": null,
  "traceId": "tr_xxx",
  "detail": { "n": 3 }     // 可选，供前端做具体交互
}
```
