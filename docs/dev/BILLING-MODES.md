# 积分计费模式：前期免费 ↔ 后期计费

> 面向：需要决定"现在收不收费"的产品/运营，以及要改这块代码的开发。
> 相关：`docs/dev/ENV.md`（环境变量）、`docs/product/青智校园_小程序详细设计文档_V2.md` 6.11、`docs/dev/ERROR-TRIAGE.md` 5.2。

## 一、结论：一个开关，一处生效

| 项目 | 值 |
|---|---|
| 开关 | 环境变量 **`BILLING_ENABLED`**（`false` = 免费开放，**当前默认**；`true` = 按积分计费） |
| 生效位置 | **只有 `apps/api/src/modules/billing/billing.service.ts` 一个类** |
| 对外呈现 | `GET /config/public` → `billing.enabled / mode / notice`（客户端据此显示价格或"限时免费"） |
| 切换成本 | **改一个环境变量 + 重启服务**。不改代码、不改数据、不跑迁移 |

`false` 时：不预扣、不结清、不退回、不写积分流水、**也不会因为"积分不足"拒绝用户**（40321 不再出现）。用户可免费使用全部工具。

## 二、为什么是"开关"而不是"删掉计费代码"

计费是一个**能力**，不是一个阶段性的临时代码：

- 删掉会连带丢失 `points_ledger` 流水、幂等与对账逻辑、三条路径（预扣/转正/退回）与它们的测试 ——
  这些是"将来一定要收费"时最贵、最容易写错的部分，重写一遍的代价远大于留着一个开关；
- 它天然是**集中式**的：所有积分变动都必须经过 `BillingService`（见下方纪律），
  所以"关掉"这一个动作就足以让整个系统变成免费，不需要去每个业务模块打补丁；
- 反过来，如果把它散落到各处（比如在 `ToolInvokeService` 里判断价格、在页面里判断文案），
  那"关掉"就会变成一次高风险的全局手术，而且必然漏。

| **`modules/billing/billing.service.ts`** | `hold` / `settle` / `refund` / `onJobTerminal` 四个入口前置短路；新增只读的 `enabled` | **是（唯一作用点）** |
| `modules/config/`（新增） | `GET /config/public`：公开配置，当前只含计费模式 | 是（内容） |

### 3.2 小程序

| 页面 | 改动点 |
|---|---|
| `utils/billing.ts`（新增） | 计费模式缓存 + **价格文案唯一出口**：`priceText()` / `costText()` / `failureHint()` / `isBillingFree()` / `showPoints()`；并且是**含"积分"二字文案的唯一出处** |
| `utils/nav.ts`（新增） | tabBar 感知的跳转（见 3.5） |
| `utils/api.ts` | 新增 `configApi.public()` 与 `PublicConfig` 类型 |
| `pages/home` | 工具卡价格 → `priceLabel` |
| `pages/toolbox` | 工具价格角标 → `priceLabel`（并保留"即将上线"优先级） |
| `pkg-toolbox/run` | 费用确认 `costLabel`；失败文案由 `failureHint()` 决定（免费期不能写"积分已退回"） |
| `pkg-toolbox/result` | "消耗 N 积分" → `costText()`；失败副标题同上（`STATUS_MAP` 里不再写死） |
| `pages/mine` | 统计项"积分" → `wx:if="{{showPoints}}"`，免费期**整项隐藏** |
| `pkg-mine/credit` | 积分 Tab、积分流水区、"如何获得积分"卡 → 免费期**整块隐藏**；带 `?tab=points` 进来会纠正回信用流水 |
| `pkg-mine/wallet` | 积分卡（余额 + 入口）→ 免费期**整块隐藏**（余额是另一套资金体系，始终展示） |

> 界面里**不再出现任何 `price > 0 ? ... : ...` 的三元判断**。这是本次改动的核心纪律：
> 价格文案只有一个出口，将来切换开关时不可能漏改某一页（否则会出现
> "首页说免费、详情页说 5 积分"这种自相矛盾的界面）。

> **免费期为什么整块隐藏积分账户，而不是改成"积分暂不扣费"**：
> 展示一个不参与任何扣费的余额只会让用户困惑（"我有 120 积分，为什么显示免费？"），
> 而需求是**界面里不出现"积分"二字**。隐藏整块 UI 同时满足这两点，
> 且切回计费模式时无需改任何代码就能恢复。

### 3.2.1 ⚠️ 客户端缓存必须会过期（曾经的真实 bug）

第一版实现是"本地存储里有值就直接用、永不刷新"：

```ts
if (cachedMode && !force) return cachedMode;   // ❌ 陈旧值永久生效
```

后果：只要某个时刻落过一次 `points`（当时确实开着计费、或接口不可用回落到了保守默认），
**之后每次启动都直接返回这个陈旧值、再也不请求接口**。于是后端明明已经改成免费，
用户却永远看到价格 —— 现象非常诡异：`GET /config/public` 明明返回 `mode: "free"`，界面却是积分。

现在两道保险：

| 保险 | 作用 |
|---|---|
| 缓存带时间戳 + TTL（5 分钟） | 长时间挂着不重启时也会自动纠正 |
| `app.onLaunch` 调 `loadBillingMode(true)` | 每次冷启动**强制**拉取一次，不走缓存 |

旧版本存储里没有时间戳，会被读成 0 → 判为过期 → 自动重新拉取，**用户无需手动清缓存**。
刷新失败时保留旧值（不把价格闪回来）；只有"从未成功拉取过"才用保守默认值。

### 3.5 tabBar 页跳转（顺手修掉的"点了没反应"）

排查计费文案时发现 6 处点击失效，根因是两个微信规则（**编译期都不报错**）：

1. `wx.navigateTo` **不能跳 tabBar 页面** —— 不报错也不跳转，纯静默失败；
2. `wx.switchTab` **不能带 query 参数** —— `?q=` 会被丢掉。

涉及：首页搜索框 / 快捷指令 / 悬浮 AI 球、工具箱智能搜索、结果页"用 AI 修改"与"生成会议纪要"
（全部是"跳到 AI 页"的动作）。修法：新增 `utils/nav.ts` 的 `openOs(query?)` ——
参数先落本地存储，AI 页在 `onShow` 里 `takePendingQuery()` 取走（取走即清空，不会重复触发）。

静态守卫：`npm run audit:mp`（见下）。

### 3.3 不随开关变化的东西（刻意保留）

| 东西 | 为什么保留 |
|---|---|
| `tool.price`（工具标价） | 它是**恢复计费后的依据**。免费期不改它，将来打开开关价格就是当初设定的值，不需要回头补数据 |
| `tool_job.cost`（作业记录里的标价） | 免费期**照常记录**，于是事后可以算出"免费期一共让利了多少积分"；若记 0，这段历史就永久丢失了 |
| `daily_quota`（每日配额） | 它是**资源保护**（GPU/第三方 API 有真实成本），不是计费。当前所有工具都是 `0`（不限），要收紧只改数据 |
| 驿站订单的**担保交易/平台服务费** | 那是**另一套资金体系**（`wallet.balance`，单位分），与积分计费无关。本次开关只影响积分 |

### 3.4 必须守住的纪律

> **除 `BillingService` 之外，任何模块都不得直接写 `wallet.points` 或 `points_ledger`。**

原因很直接：**任何绕过 `BillingService` 的写法都会同时绕过这个开关**，
于是"免费开放"就变成了假的（用户以为免费，某条路径仍在扣分）。
目前代码里确实只有 `BillingService` 在写这两张表，新增功能时请继续保持。

## 四、平滑切换的设计思路

### 4.1 三条设计原则

1. **单一真相**：开关的真相只有 `BillingService.enabled` 一处
   （`/config/public` 也是去读它，而不是自己再读一次环境变量）。
   同一份配置在两处各读一次，迟早会出现"接口说免费、实际在扣费"这种最坏的不一致。
2. **不改数据**：价格、流水、余额一律不动。切换前后是同一套数据，
   因此**可以来回切**（试运营一周再关掉也完全没问题）。
3. **客户端 fail-safe**：前端拿不到 `/config/public` 时**默认按"计费"显示价格**
   （`utils/billing.ts` 里写明了理由）——
   默认"免费"而实际在扣费，用户会在没看到价格的情况下被扣款，这是不可接受的；
   默认"计费"而实际免费，用户只是多看一眼价格，无害。

### 4.2 免费 → 计费（开始收费）

1. 确认工具标价：`tool.price`（当前 `generate_ppt` = 5，部分工具 = 0）。
   改价走数据（后台/seed），**不要改代码**。
2. 确认用户积分来源：新用户注册赠 20 分（`auth.service.ts`）；签到/任务奖励在 M4。
   —— 没有来源就收费，等于把用户挡在门外，这一步必须与积分获取渠道一起上线。
3. 提前公告（小程序公告位），避免"昨天免费今天扣分"的投诉。
4. 把 `BILLING_ENABLED` 改为 `true`，重启服务。
5. 验证：`GET /config/public` 应返回 `mode: "points"`；
   跑一次工具，`GET /user/points` 应出现一条 `-N` 的 `precharge` 流水。

**切换瞬间在途的作业**：不会错乱 —— 免费期投递的作业没有预扣行，
计费期进入终态时 `settle` 只会"无可结清"（已有单测覆盖：*免费期的作业不会被事后补扣*）。

### 4.3 计费 → 免费（暂停收费）

1. 把 `BILLING_ENABLED` 改为 `false`，重启服务。
2. **切换前建议先等在途作业跑完**（否则见下方"已知取舍"）。
   已经产生的历史预扣/消费流水保留原样 —— 流水是账，不因开关变化而改写。
3. 公告说明"限时免费"。

> ⚠️ **已知取舍（切换时要留意）**：免费模式下 `refund` 也是短路的，
> 所以"计费期预扣 → 切到免费 → 作业才失败"这一小段窗口里，那笔预扣不会被自动退回。
> 处理方式：切换前先等在途作业跑完（推荐），或切换后按流水人工补退。
> 如果将来这个窗口变得重要，可以在 `refund` 里改成"有预扣行就照退，不受开关限制"——
> 但现在没这么做，是为了让"免费模式不产生任何积分动作"这条性质保持绝对干净。

### 4.4 回滚

改回环境变量并重启即可。**没有任何迁移、没有数据改写**，因此回滚是瞬间且无损的。

## 五、这套设计的保障

- **单测**：`apps/api/src/modules/billing/__tests__/`（30 条，其中 7 条专门覆盖免费模式：
  不扣分、不写流水、余额为 0 也不报 403、连钱包行锁都不抢、所有终态都不产生积分动作，
  以及"只改开关就恢复三条路径"与"免费期的作业不会被事后补扣"）；
  `tests/mp/billing.spec.ts`（16 条，覆盖文案、积分账户显隐、**缓存刷新**与 fail-safe）。
- **两条静态守卫**（都是机器可查的红线，建议接进 CI）：
  | 命令 | 断言 |
  |---|---|
  | `npm run check:points` | `apps/mp` 下除 `utils/billing.ts` 外**不含"积分"二字**（注释除外） |
  | `npm run audit:mp` | ① 事件处理函数齐全（WXML 绑了但 TS 没写）② 没有 `navigateTo` 跳 tabBar 页 |
- **真实数据库端到端**：`node scripts/dev/verify-billing.mjs` 覆盖三条路径 + 幂等 + 对账
  （流水净额 = 余额变化）。该脚本假定计费**已开启**，验证收费链路时先打开开关。
- **接口自检**：`GET /config/public` 是判断"当前到底收不收费"的唯一入口，
  部署后打一下即可确认，不必去翻环境变量。当前返回
  `{"enabled":false,"mode":"free","notice":"限时免费开放中"}`。

## 六、后续可选（未做）

| 事项 | 说明 |
|---|---|
| 把开关做成**数据库配置**而非环境变量 | 好处是不用重启即可切换。代价是要引入配置缓存与权限（谁能改计费开关），
且"改完立刻对所有实例生效"需要跨实例通知 —— 当前规模下不值当，环境变量更简单可控 |
| 按用户/按工具灰度计费 | 例如"新用户前 7 天免费"。这需要把布尔开关升级成规则表，
届时 `BillingService.hold` 的入口签个名即可扩展，**不影响调用方** |
| 免费期让利额度报表 | 数据已经具备：`tool_job.cost` 在免费期照常记录，按时间区间求和即可 |
