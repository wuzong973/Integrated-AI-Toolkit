# 「青智校园」开发任务清单（M0~M5）

> 依据文档：`青智校园_小程序详细设计文档_V2.md`（V2.0 评审稿）
> 编制日期：2026-09-17　版本：v1.0（规划稿，**尚未生成任何代码**）
> 用途：把 V2 设计文档拆成可派工、可验收、可并行的开发任务；M0 的第一个动作是搭工程脚手架。

---

## 0. 编制口径

| 项 | 约定 |
|---|---|
| 粒度 | 单个任务 **0.5～2 人天**，超过 2 人天的已继续拆分 |
| 人天定义 | 1 人天 = 1 名熟练开发者 1 个有效工作日（含自测，不含联调返工） |
| 优先级 | **P0** 属于三条主链路必经环节；**P1** 提升体验但不阻塞主链路；**P2** 面向特定角色或需外部资质 |
| 必须/可选 | 「必须」= 不做则里程碑验收失败；「可选」= 可在里程碑内做，也可顺延，不阻塞验收 |
| 并行 | 标注 ✅ 的任务**无相互依赖，可由不同人同时开工** |
| 验收标准 | 一律写成**可观测、可复现**的判定（命令、返回码、文件、状态），不写"基本可用"这类模糊表述 |
| 范围纪律 | 只覆盖 V2 文档已定义的功能；文档未定义的一律不做，列入第 4 节"待确认" |

#### 2.2.1 计划外增量：校园小工具（2026-09-20 交付）

原计划没有这一组。起因是"学生日常高频、且**完全不需要 AI**"的几件事（算绩点、AA 分账、
考试倒计时、排课表）如果塞进工具箱，会走**作业 + 计费**链路 —— 算个绩点留一条作业记录、
扣一次额度是明显的错配。因此单独建了一个**纯本地**分包 `pkg-toolkit`。

| 工具 | 落点 | 算法 | 为什么这么做 |
|---|---|---|---|
| 绩点计算 | `pkg-toolkit/gpa` | `utils/gpa.ts` | 两种口径（4.0 区间表 / 5.0 公式），边填边算 |
| AA 分账 | `pkg-toolkit/split-bill` | `utils/split-bill.ts` | 金额一律「分」整数；贪心冲抵 ≤ 人数−1 笔 |
| 考试倒计时 | `pkg-toolkit/countdown` | `utils/countdown.ts` | **不预测考试日期**（四六级/考研每年都变），只给名称快捷填充；可**加到手机系统日历**（`wx.addPhoneCalendar`，**不引 `ics`**，见下） |
| 课程表 | `pkg-toolkit/timetable` | `utils/timetable.ts` | 按**节次**排布，不写死时钟时间；支持单双周与周次范围 |
| 抽签 / 点名 / 分组 | `pkg-toolkit/lottery` | `utils/lottery.ts` | 随机源**可注入**（优先 `wx.getRandomValues`，降级时界面如实标注）；Fisher-Yates + 拒绝采样，**不用**有偏的 `sort(() => rand() - 0.5)` |
| 行程规划 | `pkg-toolkit/trip` | `utils/trip.ts` | 按天排站点、**时间冲突当场提示**、跨午夜不误判；地图耗时与 AI 生成**尚未接入**（见下） |
| 单位换算 | `pkg-toolkit/unit-convert` | `utils/unit-convert.ts` | 2026-10-08 追加（类目对照 `iib0011/omni-tools`，MIT）。7 组互转；**存储按 1024 进制**（口径在代码里表态）；**温度不走 factor 乘算** —— 有零点偏移，只乘系数会把 0 ℃ 算成 0 ℉，且看起来像正常结果 |
| 日期差计算 | `pkg-toolkit/date-calc` | `utils/date-calc.ts` | 2026-10-08 追加。**日历日原语一律复用 `utils/date-parts.ts`**，本文件只管口径与人话文案；**周口径全仓单点**（周一在前，与 `Date.getDay()` 的周日-first 不同，混用会让周六周日整体错位且不报错）；**刻意不含节假日/调休** —— 那需要每年官方发布的放假安排，本地算不出来，凭印象编的一定是错的 |
| 字数统计 | `pkg-toolkit/text-tools` | `utils/text-tools.ts` | 2026-10-08 追加。**字数口径与后端不同且不允许修平**：后端 `countContentChars` 是"去 Markdown 语法的正文字符数"（AI 质检用），这里是 Word 式统计（汉字 + 英文单词，由 `wordCount` 唯一收口）；按行处理统一 `\r?\n` 切分并归一 LF（用户从微信/Word 粘进来的多为 CRLF，只按 `\n` 切会把 `\r` 留在行尾）；`halfWidth` 只碰 U+FF01–FF5E 镜像区，**顿号与中文引号天然不动** |

共同约定：
- **不接任何接口**，数据存本地（`wx.setStorageSync`），离线可用、不占额度；
- 纯逻辑全部落在 `apps/mp/utils/`，测试在 `tests/`（小程序发布包内不能放 spec）；
- 存储反序列化一律当成**不可信输入**，坏条目只丢自己不崩页面；
- 视觉统一用 `th-toolkit` 主题（柠黄），装饰签名见 `docs/dev/MP-VISUAL-SYSTEM.md`；
- **随机 / 概率类工具必须让随机源可注入**：算法侧一行 wx API 都不碰，
  页面侧优先密码学随机，取不到时降级并在结果上**如实标注**（`lottery` 是第一个这么做的）。

**为什么不引 `ics`**：原计划用 `ics` 包生成 `.ics` 文件来导出日历，调研后放弃了 ——
`.ics` 在小程序里**没有出口**（`wx.openDocument` 不支持它，只能"复制文本"或"转发文件"，
用户还得自己找 App 导入）；而微信自带 `wx.addPhoneCalendar`（基础库 2.15.0+），
直接写系统日历、零依赖。引 `ics` 反而要改 `project.config.json` 的 `packNpmRelationList`
（当前是空的）、占主包体积、登记 License 台账。**能跑通的功能不需要多一个依赖。**

> ⚠️ `wx.addPhoneCalendar` 的时间戳单位**官方文档没写**（中英文版都只说 "unix 时间戳"），
> 本项目按社区实践取**毫秒**。依据与"若要改该改哪里"都写在 `apps/mp/utils/calendar.ts` 文件头，
> 且 `tests/calendar.spec.ts` 有一条断言把这个选择钉住 —— 改单位会在测试里红。

**行程规划的现状与缺口**：`pkg-toolkit/trip` 目前只做"排表"这一层（数据模型 + 时间轴编辑），
这是**不可跳过的地基** —— 行程详情那两块增强都要求先有"一份行程长什么样"：

| 增强 | 依赖 | 状态 |
|---|---|---|
| **地图算距离耗时** | 高德 Web 服务（`MapProvider`，key **只在服务端**） | ✅ **后端已接入**（`npm run verify:map` 20 项断言全过）；⚠️ **小程序端还没有调用方** |
| AI 帮你排 | `EventPlanner` Agent（M2-11，未实现） | 未接 |

**地图能力落地清单**（2026-09-20）：

| 落点 | 说明 |
|---|---|
| `packages/core/src/providers/map.types.ts` | `MapProvider` 接口：坐标一律 **GCJ-02**、单位**米/秒** |
| `packages/core/src/providers/mock/mock-map.provider.ts` | 演示实现：距离按「直线 × 1.4」估算、坐标是 `(0,0)`，会被打上 `X-Provider: mock` |
| `apps/api/src/infra/providers/map/amap-map.provider.ts` | 高德 Web 服务实现 |
| `apps/api/src/modules/map/` | `GET /map/places`、`GET /map/route`（**均需登录**：消耗配额，不能公开） |
| `scripts/dev/verify-map.mjs` | 端到端验证（真实 HTTP，含"排除演示数据"的断言） |
| 环境变量 | `MAP_DRIVER`（`mock`/`amap`）、`AMAP_WEB_KEY`、`AMAP_TIMEOUT_MS` |

> ✅ **小程序端已接**（2026-09-20）：行程页底部有「算每段路」按钮（步行 / 驾车可切换），
> **用户主动点才联网** —— 编辑与存储始终是纯本地的，不点就完全不发请求。
> ⚠️ 该接口**需要登录**，未登录点击会跳登录页（刻意如此：每次调用消耗地图配额）。
> ⚠️ 站点名搜不到坐标时**跳过那一段**并如实提示"N 个地点没找到坐标"，
> **不编造坐标** —— 编出来会让"3.6 公里"变成假数据。
> ⚠️ 切换出行方式会**清空已有结果**（"步行 3.6 公里"在驾车下不成立），且**不自动重算**（避免静默消耗配额）。
>
> ⚠️ 地图与路线**只能用腾讯 / 高德 / 百度 / 天地图**；Mapbox、OSM 直连均不合规。
> 微信小程序 `<map>` 组件本身就是腾讯地图（**零 key**），但**路线规划没有原生 API**，必须走服务端。
> 参考：高德与腾讯位置服务都提供 MCP Server（含路径规划），可接进 Tool Registry。

**刻意不做占位**：不写"待接入""敬请期待"这类文案（属骨架页误导文案，`audit:mp` 会拦），
能力没到就什么都不显示。

## 5. 执行守则（写进每个任务的验收口径）

1. **不服务三条主链路的任务不进首版**（文档 1.7 反例原则）。评审会上任何"顺手加个功能"都要先回答：它服务 L1/L2/L3 中的哪一条？
2. **Mock 必须显式**：任何 MockProvider 走的链路，响应头带 `X-Provider: mock`，界面显示"演示模式"角标（红线 10）。至少保证每条主链路有**一条真实可演示路径**。
3. **单文件 ≤ 300 行、函数 ≤ 50 行、禁 `any`**，由 ESLint 强制，不靠自觉（红线 8）。
4. **状态变更必须过状态机**：订单/任务/计划/Job 四类状态机不接受任何直接赋值。
5. **合规先行**：`docs/compliance/OPEN_SOURCE_LICENSES.md` 与 `scripts/license/check-ffmpeg-license.sh` 在 M0 就要落地，任何新依赖必须先入台账再引入（文档 2.12 三条红线）。
6. **每个里程碑必须有一次端到端演示**，不许"憋大招"（文档 11.3）。
