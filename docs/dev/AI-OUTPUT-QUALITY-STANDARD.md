# AI 产出质量标准与验收指标

> 面向：写提示词的人、改渲染器的人、做交付验收的人。
> **唯一权威代码**：`packages/core/src/quality/standard.ts`（阈值常量）+ `score.ts` / `score-visual.ts`（评分器）。
> **静态守卫**：`npm run check:ai-output-quality`（标准 / 提示词 / 质检 / 图表类型四处对账）。
> 适用产出：AI 文案、AI 文档、AI PPT、AI 图表。任务编号：M1-07 / M1-08 / M1-09。

## 0. 为什么要有这份标准

改造前三个问题同时存在，而且**都不报错**：

| 维度 | 改造前的真实状态 | 用户的感受 |
|---|---|---|
| 内容生成 | 文档骨架只列章节名，提示词没有字数下限；`maxTokens` 2500-4000 | "出来就一小段，像提纲不像成品" |
| PPT 版式 | 已有 6 种版式与 5 套主题，但模型只能选 stat/quote，图表页模型无法产出 | "每页长得差不多" |
| 图表设计 | 契约只有 bar/line/pie，且三种共用同一套渲染参数 | "图就一种样子" |

标准的价值不在于把话说漂亮，而在于**能被执行、能被量出来、漂移了会失败**。
所以每个阈值都以常量形式写进 `@qz/core`，同时服务提示词、质检与 CI。

## 1. 内容生成：从"能写"到"写全、写细、写活"

### 1.1 具体改进措施

| # | 措施 | 落点 | 解决什么 |
|---|---|---|---|
| C1 | 字数下限写进 system prompt（`contentRules()`） | `modules/job/document-specs.ts` | 模型当场知道要写够多少字，而不是生成后才发现太短 |
| C2 | 必备结构要素清单写进提示词（`requiredSectionsFor()`） | 同上 | "商业计划书少了市场规模"这类结构性缺失 |
| C3 | 明确每节细节要求：每章 ≥3 段实质内容或要点，禁止只有标题无正文 | 同上 | "标题党"式空壳文档 |
| C4 | 要求二级标题 / 列表 / 表格形成层级 | 同上 | 全篇平铺、可读性差 |
| C5 | 要求每条要点写成 15-40 字、可独立阅读的完整句子 | 同上、`tool-executor.service.ts`（PPT） | 名词短语堆砌、表达单调 |
| C6 | 提高 `maxTokens`（2500→3600、3500→5200、4000→6000） | `document-specs.ts` | 提示词要求变长了，token 上限却卡着 |
| C7 | 生成后自动质检并记日志（不阻断交付，但必须可见） | `llm-tool-runner.ts` | 不达标产物悄悄流到用户手里 |
| C8 | 反注水：提示词明确"重复套话会被判不合格" | `document-specs.ts` | 用复读凑字数 |

### 1.2 产出标准

| 文档类型 | 正文字数下限 | 必备结构要素 | 细节层级要求 |
|---|---|---|---|
| 商业计划书 | **3000 字** | 项目概述 / 用户痛点 / 产品 / 市场规模 / 竞品 / 商业模式 / 团队 / 里程碑 / 风险（9 项） | 每章 ≥3 条实质信息；至少 2 层结构 |
| 活动策划 | **2200 字** | 背景 / 目标人群 / 时间地点 / 流程 / 宣传 / 物料 / 预算 / 分工 / 风险（9 项） | 同上；预算用表格 |
| 报告 | **2000 字** | 摘要 / 背景 / 现状 / 问题 / 结论 / 建议 / 后续（7 项） | 同上；结论先行 |
| 总结 | **1200 字** | 回顾 / 成果 / 不足 / 反思 / 下一步（5 项） | 同上 |
| 简历 | **900 字** | 个人信息 / 求职意向 / 教育 / 技能 / 经历 / 奖项 / 自我评价（7 项） | 量化成果、动词开头 |
| 大纲 | **800 字** | 背景 / 目标 / 方案 / 落地 / 风险（5 项） | 每个二级标题下 3-4 条要点 |
| 思维导图 | **600 字** | 核心 / 分支 / 应用（3 项） | 每层 3-6 分支，节点 4-12 字 |
| 文本摘要 | **200 字** | 要点 / 结论（2 项） | 提示词要求 N 条要点 + 一段结论；产物天然比长文短，故下限单独定 |
| 解题讲解 | **300 字** | 思路 / 步骤 / 提醒（3 项） | 提示词的三条硬要求；缺任一段即说明步骤被省略 |

> 字数口径：**正文中文字符数**，不含 Markdown 语法符号（`countContentChars()`）。
> 所有数字型内容必须标注「示例数据」「估算」或「需进一步核实」—— 丰富度**不允许**靠编造实现（红线 10）。

### 1.2b PPT 内容判据（与文档判据不同）

PPT 一页正文上限只有几条要点，**不能**用文档的"3000 字"标准去评，否则任何正常 deck 都会被误判为低分。
PPT 内容走独立判据（`scoreDeckContent()`）：

| 指标 | 阈值 | 说明 |
|---|---|---|
| 每页信息量 | ≥ **3** 条 | 要点数 + 图表/强调数据各计 1 条；低于此值是"标题页"不是内容页 |
| 要点长度 | ≥ **15** 字 | 低于此值多名词短语堆砌，非完整句子 |
| 讲稿备注覆盖率 | ≥ **60%** | 交付级 deck 需要能照着讲 |
| 空内容页占比 | ≤ **10%** | 空页过多说明结构注水 |
### 1.2c 哪些工具**刻意不接**质检

不是所有文本工具都适合套质量判据。以下两个**故意不接**，理由写在这里以免后人"补全"时误加：

| 工具 | 为什么不接 |
|---|---|
| `translate_text` | 要求**忠实原文**，没有"字数下限"语义。加质检会诱导模型为凑字数而增译或漏译 —— 那是**降低**译文质量 |
| `generate_image_prompt` | 产物是提示词，无结构义务。强套章节要求会得到"有格式但不好用"的提示词 |

判据是"这次产出有没有可核对的完整性义务"，而不是"它是不是 AI 生成的"。
### 1.3 量化验收指标

- **内容完整性评分 ≥ 85 分**（百分制，见 §4 权重）；
- 字数达标率 = 1.0（不得低于下限）；
- 必备要素覆盖率 = `已命中要素数 / 必备要素数` ≥ 0.9；
- 结构层级 ≥ 2 层（一级标题 + 列表/表格/二级标题）；
- 句长标准差 ≥ 6（低于即"全篇一个句式"，判表达单调）；
- **二元词组去重率 ≥ 0.25**（低于即复读注水，实测注水文本约 0.12）。

## 2. PPT 版式与视觉：建立排版秩序与视觉层次

### 2.1 具体改进措施

| # | 措施 | 落点 | 解决什么 |
|---|---|---|---|
| P1 | 统一画布与安全区：16:9（13.333"×7.5"），左右边距 0.62"，正文区 1.62"~6.5" | `ppt-layouts.ts`（BODY/PAGE） | 每页边距不一致、元素贴边 |
| P2 | 统一标题层级：封面 40pt / 章节 32pt / 页标题 24pt / 正文 14-16pt / 脚注 9-10pt | `pptxgenjs.provider.ts`、`ppt-draw-layouts.ts` | 字号随手写，层级混乱 |
| P3 | 六种版式按数据条件自动分发与降级（bullets / twoCol / stat / quote / chart / section） | `ppt-layouts.ts`（resolveLayout） | 全是同构 bullet 页 |
| P4 | 相邻同构页自动去重：连续挤满要点时第二页改双栏 | `dedupeAdjacentLayouts()` | "九页同一张脸" |
| P5 | 5 套主题色板（商务/科技/清新/学术/国潮），每套含主/辅/点缀 + 三级文字 + 封面/章节底色 | `ppt-themes.ts` | 选风格画出同一张片子 |
| P6 | 图表页开放给模型，并强制轮换 stat / quote / chart | `tool-executor.service.ts` 提示词 | 数据页形态单一 |
| P7 | 生成后视觉质检（`analyzeDeck()`）并记日志 | `tool-executor.service.ts` | 版式单一无感知 |

### 2.2 版式规范（可执行）

**配色方案**

- 单页最多 3 个语义色：主色（标题/序号/强调）、辅色（面板/分隔）、点缀色（细线/高亮）；
- 正文区底色只用 `bgPage`，强调区用 `mix(bgPage, primary, 0.05~0.07)` 的浅色，不引入第 4 种色相；
- 所有 hex 只允许出现在 `ppt-themes.ts`，其余文件一律经 `theme.xxx` 取色（红线 2 的收口做法）。

**留白节奏**

- 内容区面积占比 0.5~0.78，超过 0.78 判"没有留白"；
- 页脚细线固定在 y=6.98"，正文不得越过 6.5"；
- 卡片行间距 ≥0.16"，双栏中缝 0.42"。

**对齐规则**

- 左对齐为默认；页码右对齐；数字类内容可居中；
- 所有内容元素左边界对齐到 x=0.62"（`BODY.x`），标题、正文、卡片共用同一条隐形轴线；
- 装饰条长度固定（主 0.62" + 点缀 0.2"），不随标题长度变化。

**字体层级**

| 层级 | 字号 | 字重 | 用途 |
|---|---|---|---|
| 封面主标题 | 40pt | Bold | 封面 |
| 章节标题 | 32pt | Bold | section 页 |
| 页标题 | 24pt | Bold | 内容页 |
| 卡片序号 | 14pt | Bold | bullets |
| 正文 | 14-16pt | Regular | 正文 |
| 脚注 / 页码 | 9-10pt | Regular/Bold | 页脚 |

### 2.3 量化验收指标

- **版式多样性达标率 ≥ 0.8**：页数 ≥8 时至少覆盖 **4 种**版式；
- 相邻同版式连排 ≤ **2** 页（超过即判同构，一致性维度扣分）；
- 内容区面积占比 ≤ **0.78**；
- 主题色板独立性：5 套主题主色去重后仍为 5；
- **视觉一致性必须满分**：任一页存在越界/重叠/缺色板即不合格（硬指标）。

## 3. 图表设计：打破样式单一

### 3.1 具体改进措施

| # | 措施 | 落点 | 解决什么 |
|---|---|---|---|
| G1 | 图表类型从 3 种扩到 **9 种**（bar / bar3D / line / area / pie / doughnut / radar / scatter / bubble） | `providers/types.ts` | "图就一种样子" |
| G2 | 每种类型独立渲染参数（柱间距/折线符号/环形孔径/雷达样式/散点尺寸） | `ppt-chart-style.ts`（typeOptions） | 三种图共用一套参数 |
| G3 | 统一的图表配色：主题三色 + 1 混色，上限 4 色 | `chartColors()` | 彩虹图 |
| G4 | 统一字号下限：轴标签/图例 11pt、数据标签 10pt | `ppt-chart-style.ts` | 投影看不清 |
| G5 | 图例位置按类型选择：占比图靠右、趋势图靠下 | 同上 | 图例永远堆底部 |
| G6 | 数据标签按类目数自适应（≤6 类且 ≤2 系列才显示） | `shouldShowValues()` | 标签糊成一片 |
| G7 | 坐标轴类图表保留浅网格，占比图不画网格 | 同上 | 视觉噪音 |
| G8 | 图表选用逻辑写入提示词（`PPT_CHART_GUIDE` 同源） | `tool-executor.service.ts` | 模型不知道什么时候该用雷达图 |
| G9 | 模型可产出带真实数据的 chart 页，数据不全自动降级回 bullets | `ppt-layouts.ts`（normalizeChart） | 画空图 |
| G10 | **上传表格 → 真实数据图表**：读取 CSV/TSV，按类目聚合真实数值列，插成一页真实图表 | `ppt-data-source.ts` + `table-chart.ts` | 用户上传了表格，PPT 里却只有模型编的数字 |
| G11 | 图表标注按来源区分：有 `caption` 显示真实来源，没有仍标「示例数据」 | `ppt-chart-style.ts` | 真实数据与示例数据被混淆 |

### 3.2 图表选用逻辑（唯一标准）

| 类型 | 标签 | 什么时候用 |
|---|---|---|
| `bar` | 柱状图 | 类目数量对比或排名（各院系人数、各渠道订单量） |
| `bar3D` | 立体柱状图 | 需要更强视觉冲击的少数关键对比，正式答辩慎用 |
| `line` | 折线图 | 随时间变化的趋势（月度增长、周活变化） |
| `area` | 面积图 | 既看趋势又看累积量感（累计注册用户） |
| `pie` | 饼图 | 单一整体下的占比，且类目 ≤5 |
| `doughnut` | 环形图 | 占比展示 + 中心放合计值或关键结论 |
| `radar` | 雷达图 | 多维能力/指标画像对比（团队能力雷达） |
| `scatter` | 散点图 | 两个数值变量的相关性（投入与产出） |
| `bubble` | 气泡图 | 三个变量关系，第三个用点的大小表达 |

### 3.3 统一设计规范

- 配色：只用主题色，单图 ≤4 色；同一 deck 内同一语义用同一色；
- 字号：轴标签/图例 ≥9pt（实现取 10-11pt）；标题 11pt；
- 标注：数据非真实时必须显示「示例数据（请替换为你的真实数据）」；stat 含数字必须挂「AI 估算，请核实」；
- 尺寸：单图系列 ≤4，类目 ≤12（超出应改 Top-N、分面或表格）；
- 可编辑：一律用 PptxGenJS 原生图表，禁止贴图。

### 3.3b 真实数据链路（上传表格 → 图表）

用户上传 CSV/TSV 时，`generate_ppt` 会读第一个表格文件，抽出一页**真实数据图表**。
这一页的数字来自表格本身，不经过模型，因此标注为「数据来源：上传表格真实统计」。

**选图逻辑（按数据结构，不按好看）**：

| 数据形态 | 图表 | 理由 |
|---|---|---|
| 类目列有顺序（月份/季度/年级） | 折线 | 时间趋势不能用占比表达，否则是**语义错误** |
| 类目 ≤5 且无顺序 | 环形 | 构成关系，环心可放合计 |
| 其余类目对比 | 柱状 | 排名 / 数量对比最直观 |
| 只有多列数值 | 柱状（各列均值） | 退而求其次，但仍是真实数字 |
| 只有一个数值列 | 柱状（min/均值/中位/max） | 展示分布轮廓 |

**聚合口径**：同一类目多行时**求和**（与用户在 Excel 拉透视表的直觉一致）。
无序类目按数值排序取 Top-6，有序类目保留原顺序。

**降级纪律（红线 10）**：

- 文件读不到 / 不是表格 / 只有一列 / 全是文本 → 返回 `undefined`，**不阻断 PPT 生成**，该页回落文字版式；
- 此时**绝不**把这页标成「真实数据」；模型该用示例数据就继续用，并标注「示例数据」；
- 疑似学号/订单号这类标识列**不参与**绘图（均值在数学上成立、业务上无意义）。
### 3.4 量化验收指标

- **图表多样性达标率 ≥ 0.8**：一套 deck 内 ≥2 张图时，至少覆盖 **2 种**图表类型；
- 单图配色数 ≤ **4**；单图系列数 ≤ **4**；单图类目数 ≤ **12**；
- 轴标签/图例字号 ≥ **9pt**；
- 图表类型渲染成功率 = **100%**（9 种类型均有冒烟测试覆盖）；
- 数据不全的 chart 页降级率 = 100%（不得产出空图）。

## 4. 综合评分与验收阈值

### 4.1 权重

| 维度 | 权重 | 组成 |
|---|---|---|
| 内容完整性 | **45%** | 文档：篇幅 30% + 要素覆盖 30% + 细节 16% + 层级 12% + 节奏 6% + 用词 6%；PPT：每页信息量 40% + 要点长度 25% + 讲稿备注 20% + 空页 15% |
| 多样性 | **30%** | 版式多样性 70% + 图表多样性 30% |
| 视觉一致性 | **25%** | 同构连排 + 留白达标（满分/0.5 两档） |

### 4.2 验收阈值（达不到即"未交付"）

| 指标 | 阈值 | 判定方式 |
|---|---|---|
| 综合质量分 | **≥ 85** | `analyzeDeck()` / `analyzeContent()` |
| 内容完整性评分 | **≥ 85** | `analyzeContent()` |
| 多样性达标率 | **≥ 0.8** | 版式与图表多样性加权 |
| 视觉一致性 | **= 1.0（必须满分）** | 硬指标，任一违例即不合格 |
| 版式多样性 | **≥ 0.8**（页数 ≥8 时 ≥4 种） | `scoreVisual()` |
| 图表多样性 | **≥ 0.8**（≥2 张图时 ≥2 种） | `scoreCharts()` |
| 评分等级 | ≥90 优秀 / ≥85 良好 / ≥70 及格 / <70 不合格 | `gradeOf()` |

### 4.3 怎么跑

```bash
npm run check:ai-output-quality   # 标准 / 提示词 / 质检 / 图表类型四处对账
npx vitest run packages/core/src/quality apps/api/src/infra/providers/ppt
```

### 4.4 不达标时的处置

- **提示词阶段**：模型收到明确下限，属于"预防"；
- **质检阶段**：`analyzeContent()` / `analyzeDeck()` 打分，不达标**不阻断交付但记 warn 日志**（保证用户仍拿得到产物，同时问题可见）；
- **CI 阶段**：`check:ai-output-quality` 对账失败即构建失败，防止标准与实现漂移。

> 为什么质检不直接阻断：生成失败会让用户一无所获，而"内容略短但可用"仍是可用产物。
> 处置原则与 `data-tool-runner.ts` 一致 —— **降级必须可见**，不是悄悄换个结果（红线 9/10）。
